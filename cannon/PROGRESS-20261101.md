# MIUI14 display checkpoint, 2026-11-01

**test68 has visible output confirmed on the phone by the user.** The runtime
firmware is official V14.0.6.0.SJECNXM. Its HWC and SELinux policy have not been
replaced. This is a display bring-up milestone, not a completed phone port:
sys.boot_completed and user CE availability were still unset.

The working source is the 6.12 baseline, Clang/LLD 13, with 72 modules staged
into the boot ramdisk. The common kernel is bc759b157. test68 boot image:
SHA256 4e15eb9d84b423a830d89f6ebf65c794b4fec8abaf4ef35657467d2aa23b62c0.
Only boot was flashed for these kernel tests; LK, Preloader and the independent
DTBO were left unchanged. The boot ramdisk retains adb root diagnostics,
pstore/expdb recording and the finite 600-second recovery watchdog.

## Verified progression

- Mali accepts the official vendor's 72-byte job atoms; the normal GPU ID
  reads no longer flood dmesg. Firmware was already built into the common
  kernel in bc759b157.
- test63 removed unsupported MT6853 DSI self-pattern/target-line writes and
  corrected diagnostic register offsets. RDMA scan positions and actual DSI
  interrupts showed that the LK display handoff was running.
- test64 supplied legacy plane alpha properties and disabled-only CRTC
  compatibility properties. Mandatory HWC object discovery succeeded. Atomic
  tracing then identified the separate `active without enabled` failure.
- test65 published the real initial panel mode with an atomic transaction
  before registering DRM. The main CRTC became enabled/active at 1080x2340.
- test66 selected the J22 0a panel's existing DCS 0x0A=0x9C ESD check. The
  external TE IRQ check had triggered false recovery and destroyed the LK
  stream. ESD remained enabled. MT6853's shadow offset was also corrected to
  0x190. The saved 256-second run had no ESD recovery or WAIT EVENT 410 timeout.
- test67 translated the official HWC's 128-byte layering request and 60-byte
  layer arrays. Real HRT calculation succeeded; the earlier setupHwcLayers
  crash was no longer seen. Standard GET_CAP and six invalid-input checks
  passed. Core then rejected AB30 with the old private blend modifier.
- test68 retains that verified RGB blend hint privately for OVL and gives
  core KMS an accepted modifier. DSI/RDMA/GPU interrupts and actual frame
  submissions progress, and the user confirmed the visible animation/image.

Details: BOOT-MODE.md, HWC-ABI.md, LAYERING-ABI.md and DSI-TEST63.md.
Host evidence is under device-cannon/test63 through test68 in the parent
workspace. Those large device logs/images are not included in this repository.

## Next blocker

The saved Android Watchdog trace identifies the main thread blocked at
VibratorManagerService.nativeGetVibratorIds(). The official vibrator HAL
exits with ENODEV because its kernel interface is absent. The baseline's
regulator-vibrator module is already built, but the official DTBO provides
the old mediatek,vibrator node, and the HAL needs duration/activate attributes.
The real VIBR regulator was present at 2.8 V and disabled during the test.

The following pending HAL patch is kept in a separate commit. It has not
been flashed or validated on the phone at this checkpoint. Other phone
functions, including touch, modem, audio and sensors, are not established
as working by the display tests.
